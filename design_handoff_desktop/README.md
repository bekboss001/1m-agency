# Handoff: 1M Agency — ПК-версия (десктоп)

## Overview
Десктопная (веб) версия внутренней платформы агентства 1M.AGENCY для управления контентом клиентов. Четыре раздела: **Таблица** (доска клиентов), **Контент-план**, **Съёмки**, **Настройки**. Ключевая задача продукта — быстро менять два поля: **количество выпущенных постов** и **дату выкладки**, поэтому эти два действия вынесены в один клик прямо на карточке клиента.

Мобильная версия того же продукта живёт в `1M Agency App.dc.html` (в корне проекта) и уже согласована — десктоп должен ей соответствовать по палитре и тону, но использует другую навигационную модель (верхняя панель вместо табов внизу).

## About the Design Files
Файлы в этом бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие внешний вид и поведение, а **не продакшн-код для копирования**. Задача: **воссоздать эти макеты в существующей среде целевого проекта** (React / Vue / Next.js и т.д.), используя принятые в кодовой базе паттерны, компоненты и библиотеки. Если среды ещё нет — выбрать подходящий фреймворк и реализовать дизайн в нём.

Файлы используют собственный маленький рантайм (`support.js`, теги `<x-dc>`, `<sc-for>`, `<sc-if>`, `<dc-import>`). **Не переносите этот рантайм в проект** — он нужен только чтобы макет открывался в браузере. Читайте из него разметку, стили, данные и логику.

- `1M Agency Desktop.dc.html` — оболочка: верхняя панель навигации + подключение экранов.
- `DesktopScreens.dc.html` — все четыре экрана и вся логика/моковые данные.
- `support.js` — рантайм прототипа, в продакшн не нужен.

Открыть: положить все три файла в одну папку и открыть `1M Agency Desktop.dc.html` в браузере.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, радиусы и состояния финальные — воссоздавать пиксельно, но существующими компонентами кодовой базы. Дизайн нарисован под фиксированный **1440×900** (ноутбук). Данные внутри — моковые, брать из API.

## Interactions & Behavior

- **Навигация**: клик по табу меняет активный экран; состояние вкладки хранится в оболочке. Состояние внутри экранов (фильтры, выбранный клиент, выбранный день) сохраняется при переключении.
- **Таблица**:
  - `+` → `done = min(total, done + 1)` и `out = today`.
  - Клик по пипсу `i` → `done = (i === done ? i - 1 : i)` и `out = today`.
  - «Сегодня» → `out = today` без изменения счёта.
  - Изменение `input[type=date]` → `out = value`.
  - Смена СММ/оператора — сразу применяется.
  - Поиск: подстрока в названии клиента, регистронезависимо. Фильтры СММ/оператор и срез («есть остаток» = `total - done > 0`, «договор истекает» = `days(end) ≤ 14`) складываются. Счётчики на пилюлях считаются от результата поиска и селектов, но **без** учёта самого среза.
  - `+ Клиент` добавляет карточку: «Новый клиент», план 12, выпущено 0, дата = сегодня, СММ/оператор не назначены.
- **Контент-план**: все поля правятся инлайн, изменения мгновенные (без кнопки «Сохранить»). Удаление — сразу. Метрики и счётчики в списке клиентов пересчитываются на месте.
- **Съёмки**: клик по ячейке выбирает день (дни вне месяца не кликабельны). Правки съёмки применяются мгновенно.
- **Настройки**: переключатели и селекты ролей — оптимистично, мгновенно; заявки исчезают из списка при «Принять»/«Отклонить».
- **Hover** — везде изменение фона (`#0e0e0e → #121212/#131313`); focus у инпутов — лаймовая рамка через `inset box-shadow`; переходов/анимаций в макете нет (можно добавить `transition: background 120ms ease` при желании).
- **Responsive**: дизайн под 1440×900 фиксированный. Сетки карточек уже `auto-fill/minmax`, так что на более широких экранах добавляются колонки; ниже ~1280px нужно решение отдельно (не спроектировано).

## State Management

Оболочка: `tab: "table" | "plan" | "shoots" | "settings"`.

Экраны:
- `clients: { id, name, color, total, done, out (ISO), end (ISO), smm, operator }[]`
- `query`, `smmFilter`, `opFilter` (`"all" | имя | "—"`), `rowsMode` (`"all" | "open" | "soon"`)
- `activeClient: string` — выбранный клиент в контент-плане
- `posts: Record<clientName, { id, theme, type, date (ISO), status }[]>`
- `shoots: { id, date (ISO), time "HH:MM", client, place, operator, status }[]`
- `selected: ISO` — выбранный день календаря; `newShootClient`, `newShootTime`, `newShootPlace`
- `settingsTab`, `notif: { shoot, deadline, digest, target }`, `integrations: { ig, fb, tg, drive }`
- `users: { id, name, email, role, scope }[]`, `requests: { id, name, email, wants, when }[]`

«Сегодня» в прототипе зашито как `2026-09-07` (см. `days()` / литералы `"2026-09-07"` в `DesktopScreens.dc.html`) — в реальной реализации заменить на текущую дату. Календарь тоже захардкожен на сентябрь 2026 (сетка 5×7 с началом недели в понедельник, 1 сентября = вторник) — нужна нормальная генерация месяца + переключение месяцев (в макете кнопок переключения нет, стоит добавить).

Данные должны приходить с бэкенда; типы полей — как в моках. Все правки — оптимистичные апдейты с откатом при ошибке.
