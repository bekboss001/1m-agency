# Handoff: мобильное приложение 1M.AGENCY (редизайн)

## Overview
Мобильное приложение для SMM-агентства 1M.AGENCY: 15 клиентов, контент-план, съёмки, таргет-аналитика.
Редизайн существующего приложения. Три главные задачи, которые решает этот дизайн:

1. **«Не видно, что делать сегодня»** → главный экран стал списком дел на сегодня вместо витрины цифр.
2. **«Слишком много чипов клиентов»** → облако из 15 чипов заменено одним селектором клиента + bottom-sheet со списком.
3. **«Долго менять статус поста»** → статус меняется одним тапом по чипу (цикл из 4 статусов), без открытия карточки и без dropdown.

Плюс новый экран — **карточка клиента целиком**, и **отдельный селектор клиента на экране «Таргет»** (независимый от контент-плана).

## About the Design Files
Файл в этом бандле — **дизайн-референс, сделанный в HTML** (`1M Agency App.dc.html`): прототип, показывающий внешний вид и поведение. Это **не продакшн-код для копирования**.

Задача — **воспроизвести эти экраны в существующем окружении приложения** (React Native / Flutter / SwiftUI / Kotlin — что используется в проекте), опираясь на принятые в кодовой базе паттерны, навигацию и библиотеки. Если окружения ещё нет — выбрать подходящий стек и реализовать дизайн в нём.

Как открыть прототип: открыть `1M Agency App.dc.html` в браузере. На канвасе три варианта:
- **1a** — интерактивный прототип, все экраны (это основной вариант для реализации);
- **1b** — альтернативная главная («лента дня», крупная типографика, без карточек);
- **1c** — светлая тема как альтернатива.

**Реализовывать нужно 1a.** 1b/1c — направления на будущее, если заказчик их выберет.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы, радиусы и состояния — финальные, воспроизводить точно. Данные (клиенты, посты, суммы) — демо-данные, приходят с бэкенда.

- **Три плитки**: `ОСТАЛОСЬ ПОСТОВ / СЪЁМКА(-ОК) В ПЛАНЕ / ТАРГЕТ / 30 ДН` (Oswald 700 22px + Mono 500 8.5px). Подпись числа склоняется по количеству.

## Interactions & Behavior

| Действие | Результат |
|---|---|
| Таб-бар (5 таб) | смена экрана; активный таб — акцентный текст + полоска 22×2 над подписью |
| Тап по делу на главной | переключение выполнено/нет; счётчик пересчитывается; тост `ГОТОВО: …` |
| Тап по клиенту в «требуют внимания» | переход на карточку клиента |
| `← НАЗАД` в карточке клиента | возврат на главную |
| Тап по чипу статуса поста | статус → следующий по циклу из 4; тост `СТАТУС → …` |
| Тап по селектору клиента | bottom-sheet; выбор закрывает лист и показывает тост `КЛИЕНТ: …` |
| Селекторы в «Контенте» и «Таргете» | **независимые состояния**, один и тот же компонент листа |
| Тап по дню в недельной полосе съёмок | переключение дня; таймлайн и сводки пересчитываются |
| Тап по строке клиента в таргете | раскрытие 4 метрик (аккордеон, одна строка за раз) |
| FAB | создание черновика поста/съёмки (в прототипе — тост) |
| Тост | absolute, left/right 20px, bottom 104px, фон `#fff`, текст `#0A0A0B`, radius 14, Mono 600 12px, точка-индикатор 8px акцентом, shadow `0 12px 30px rgba(0,0,0,.5)`; авто-скрытие через 1900ms, новый тост сбрасывает таймер |

Все интерактивные элементы — минимум 44px по высоте (чипы статуса — 32px, допустимо как second-tier контрол; при реализации увеличить hit-area до 44px через padding/hitSlop).

Анимации в прототипе намеренно минимальны. При реализации: bottom-sheet — slide-up 240ms ease-out + фейд оверлея; тост — fade+slide 8px 160ms; смена статуса — цветовой transition 120ms; смена таба — без анимации либо кросс-фейд 120ms.

## State Management
```
tab: 'home' | 'content' | 'shoots' | 'target' | 'profile' | 'client'
client: string            // выбранный клиент в контент-плане и карточке
targetClient: string      // 'all' | id — отдельный выбор в таргете
view: 'list' | 'cal'      // вид контент-плана
statusFilter: 'Все' | 'Идея' | 'В работе' | 'На проверке' | 'Опубликовано'
statuses: {postId: status}    // локальные оптимистичные изменения статусов
doneTasks: {taskId: boolean}  // отмеченные дела на сегодня
picker: boolean               // открыт bottom-sheet
pickerMode: 'content' | 'target'  // чей выбор редактируем
shootDay: number              // выбранный день в съёмках
period: 'Вчера' | 'Сегодня' | '7 дней' | '30 дней' | 'Этот месяц'
openRow: string | null        // раскрытая строка в таргете
toast: string | null
```

**Данные с бэкенда:** список клиентов (id, имя, цветовая метка, план/сделано за месяц), посты (id, клиент, заголовок, тип, дата, мета, статус), съёмки (день, время, клиент, состояние, объект, состав команды), таргет-метрики по клиенту и периоду (расход, охват, клики, переписки, дельта), команда, дела на сегодня (агрегируются из съёмок, постов на проверке и дедлайнов планов).

**Смена статуса** — оптимистичное обновление + откат при ошибке (это самое частое действие в приложении, нельзя ждать ответ сервера).
**Дела на сегодня** — серверный агрегат, а не отдельная сущность: съёмки этого дня + посты на проверке + дедлайны планов, отсортированные по времени.
