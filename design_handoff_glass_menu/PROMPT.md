Я переделываю навигацию в мобильном приложении 1M.AGENCY (тёмная тема, лаймовый акцент, эстетика liquid glass).

В папке `design_handoff_glass_menu/` лежит дизайн-референс: `menu-design-reference.dc.html` (открой в браузере — это HTML-прототип, **не** production-код) и два скриншота текущего состояния (`current-menu-before.png`, `current-home-before.png`). Полная спецификация — в `README.md` этой же папки: точные цвета, размеры, типографика, состояния и поведение.

Задача — реализовать вариант **2a + 2b** (liquid glass) в нашем кодовом стеке, по нашим существующим компонентам и паттернам, а не копировать HTML:

1. **Кнопка «Меню»** — пятая вкладка таб-бара, стеклянная, 4 состояния (покой / нажатие / открыто-крест / точка-событие). Спецификация в разделе «2b».
2. **Bottom sheet «Разделы»** — вместо текущего всплывающего меню: поиск, сгруппированный список строк (РАБОТА / АНАЛИТИКА / КОМАНДА), бейджи-счётчики, переключатель темы и карточка профиля в закреплённом футере. Спецификация в разделе «2a».
3. **Кнопку «Выйти» из меню убрать полностью.** Выход живёт на экране Профиля (тап по карточке профиля в листе ведёт туда). Это ключевое требование: деструктивное действие не должно жить в навигации.

Правила реализации:
- Переиспользуй существующие в проекте компоненты (sheet/modal, list row, badge, segmented control, иконки) — новые примитивы создавай, только если аналога нет.
- Значения из README — целевые; если в проекте есть токены с теми же ролями, используй токены, а не хардкод.
- Хит-таргеты не меньше 44pt, контраст мелкого текста не ниже 4.5:1.
- Жесты: свайп вниз и тап по затемнению закрывают лист; открытие/закрытие — 280–320 мс, spring/ease-out.
- Если backdrop-blur недоступен на целевой платформе — фолбэк на непрозрачный `#131513` с той же геометрией.

Сначала покажи план: какие файлы затронешь, какие компоненты переиспользуешь, где появится экран выхода. Потом реализуй.
