# Handoff: экспорт контент-плана в PDF (A4)

## Обзор
Шаблон документа, который приложение отдаёт при экспорте контент-плана клиента:
титульная страница + постраничная таблица публикаций + сводка по каналам.
Документ предназначен для печати/PDF на A4 (портрет) и для отправки клиенту
агентства, поэтому вёрстка жёстко разбита по страницам — одна страница макета =
одна страница PDF, без «плавающих» переносов внутри строк таблицы.

## О файлах в этом бандле
Файлы `Контент-план v3.dc.html` и `doc-page.js` — **дизайн-референс, сделанный в
HTML**: прототип, показывающий итоговый вид и правила пагинации. Это не
продакшн-код для копирования. Задача — **воспроизвести этот документ в
окружении вашего кодовой базы** (React + серверный рендер в PDF через
Puppeteer/Playwright, или любой текущий PDF-пайплайн: WeasyPrint, wkhtmltopdf,
react-pdf) по принятым в проекте паттернам. Если пайплайна ещё нет — выбрать
подходящий; рекомендация ниже в «Пагинация».

`doc-page.js` — вспомогательный веб-компонент прототипа: он рисует лист,
фон стола и печатную геометрию (`@page { margin: 0 }`). В продакшене его роль
выполняет ваш рендерер; повторять компонент не нужно, нужны его правила
(размер листа, отсутствие браузерных колонтитулов, `overflow: hidden` на листе).

## Точность
**Hi-fi.** Цвета, типографика, отбивки и линии финальные — воспроизводить
пиксельно. Источник стилей — дизайн-система **Modernist** (`_ds/modernist-*/styles.css`):
Archivo, красный акцент `#ec3013`, нулевые радиусы, сильные 2px линии, всё по
левому краю. Если в кодовой базе эта дизайн-система уже подключена — брать
значения из её токенов (`var(--color-*)`, `var(--space-*)`), а не хардкодить хексы.

## Геометрия страницы
- Лист: A4 портрет, 210 × 297 мм (794 × 1123 px при 96dpi).
- Внутренние отступы листа: `52px` сверху/снизу, `46px` слева/справа
  (≈ 13.7 мм / 12.2 мм). Полоса набора — 702 px.
- Полезная высота под контент: **1019 px** (A4). Проверять также по Letter
  (952 px), если у клиента американская бумага, — макет должен влезать в обе.
- Лист — `overflow: hidden`, содержимое обязано влезать; никаких `vh`,
  `position: fixed`, `sticky` внутри контента.
- Колонтитул страницы прижат к низу листа (`margin-top: auto` во flex-колонке
  с `min-height: 100%`).

## Страницы
### Стр. 1 — Титул
Порядок блоков сверху вниз, вертикальный `gap: 32px`:
1. Плашка логотипа: `132 × 44 px`, рамка `2px solid #201e1d`, внутри текст
   «ЛОГОТИП» 10.5px/700, `letter-spacing: 0.14em`, uppercase, `#605d5d`,
   выключка влево, отступ `0 10px`. Справа от плашки — красная линия
   `height: 2px; background: #ec3013; flex: 1`, отбивка 16px.
2. Киккер: имя клиента, 11px/700, `letter-spacing: 0.16em`, uppercase, `#ec3013`.
3. H1: 62px/800, `line-height: 0.96`, `letter-spacing: -0.035em`, uppercase,
   принудительный перенос в две строки («КОНТЕНТ-» / «ПЛАН»).
4. Подзаголовок периода: 24px/600, `letter-spacing: -0.01em`.
5. Линия `2px #201e1d`.
6. Сводка: grid из 4 равных колонок. В каждой — число 36px/800
   (`letter-spacing: -0.03em`, `line-height: 1`) и подпись 10.5px/600,
   `letter-spacing: 0.1em`, uppercase, `#605d5d`. Разделители — `1px solid #d7d3d3`
   по правому краю колонок (у последней нет), внутренние отступы 16px.
7. Линия `2px #201e1d`.
8. Двухколоночный блок `1.5fr / 1fr`, `gap: 40px`:
   слева «ФОКУС МЕСЯЦА» (заголовок 11px/700, `ls .14em`, uppercase, `#605d5d`) +
   абзац 13px/1.6; справа «СОГЛАСОВАНИЕ» — три строки «ключ / значение»
   (12px, ключ `#444141`, значение 600), разделённые `1px #d7d3d3`.
9. Колонтитул: агентство / дата экспорта и версия / «Стр. 1 / N».

### Стр. 2—N-1 — Таблица публикаций
1. Шапка страницы: H2 «ПЛАН ПУБЛИКАЦИЙ» 19px/800, `ls -0.02em`, uppercase; справа —
   контекст 10.5px/600, `ls .1em`, uppercase, `#605d5d` («Волна · Октябрь 2026»,
   «Продолжение», «Завершение месяца»). Снизу линия `2px #201e1d`, отбивка 8px.
2. Таблица: `table-layout: fixed`, `border-collapse: collapse`.
   Колонки: `66px` (дата) · `86px` (канал) · авто (публикация) · `112px` (KPI и статус).
   Межколоночный зазор задан правым `padding: 12px` у ячеек; у последней колонки — 0.
3. `thead`: 10px/700, `ls .1em`, uppercase, нижняя граница `1px solid #201e1d`,
   `padding-bottom: 7px`. Шапка повторяется на каждой странице таблицы.
4. Разделитель недели — строка `colspan="4"`: 10.5px/700, `ls .12em`, uppercase,
   `#605d5d`; первая на странице `padding: 12px 0 6px` без верхней границы,
   последующие — `padding: 14px 0 6px` и `border-top: 2px solid #201e1d`.
5. Строка публикации: `vertical-align: top`, `padding: 9px 12px 9px 0`,

   `border-bottom: 2px solid #201e1d`.
   - Дата: `13.5px/700`, `ls -0.01em`; под ней день недели и время

   - Канал: 12px/600; под ним формат 10.5px/500, `ls .06em`, uppercase, `#605d5d`.
   - Публикация: заголовок 12.5px/600, `line-height: 1.35`; описание 11.5px/1.45,
     `#444141`, `padding-top: 2px`, `text-wrap: pretty`; строка референса визуала

   - KPI и статус: KPI 11.5px/1.35 `#201e1d`; статус 10px/700, `ls .06em`,

## Пагинация (главное правило экспорта)
В прототипе разбивка сделана вручную: 4 листа, 4 + 2 / 2 + 4 / 4 публикации.
В приложении она должна считаться **до рендера**, набором страниц:

1. Измеренные высоты (A4, полоса набора 702px):
   - шапка страницы таблицы ≈ 40px + 16px gap;
   - `thead` ≈ 25px;
   - разделитель недели ≈ 30px;
   - строка публикации ≈ 105–135px (зависит от числа строк заголовка/описания);
   - колонтитул ≈ 25px + 16px gap.
2. Алгоритм: набирать строки в текущую страницу, пока
   `сумма высот + chrome ≤ 1019px` (A4) / `952px` (Letter); при переполнении —
   новая страница с повтором шапки и `thead`, а разделитель недели переносится
   с пометкой «Неделя N · продолжение».
3. Строка публикации **никогда** не разрывается между страницами.
4. Если высота строки заранее неизвестна (длинные заголовки), считать её
   измерением в рендерере (Puppeteer: `getBoundingClientRect` на пробном
   проходе) либо ограничить копирайт: заголовок ≤ 2 строк, описание ≤ 2 строк
   (`-webkit-line-clamp: 2`), референс визуала — 1 строка.
5. Сводка по каналам ставится в конец последней страницы, если остаётся
   ≥ 240px; иначе — отдельным листом.
6. Нумерация «Стр. N / M» подставляется после того, как известно M.

## Данные
Одна публикация:

```ts
type Post = {
  date: string;        // ISO, в документе — DD.MM
  weekday: string;     // «чт»
  time: string;        // «10:00»
  channel: string;     // Telegram | Instagram | VK | Email
  format: string;      // Пост | Reels | Stories | Клип | Рассылка | Опрос | Анонс
  title: string;
  description: string;
  visualRef: string | null;   // null → «Визуал: не требуется»
  kpi: string;
  status: 'approved' | 'in_review' | 'draft';
};
```

Документ: клиент, период (месяц), логотип, менеджер, дата утверждения, круг
правок, текст фокуса месяца, счётчики титула (публикации, каналы, рубрики,
креативы), распределение по каналам, дата и версия экспорта.
Счётчики и распределение считаются из массива публикаций, не вводятся руками.

Статусы: `approved` → «Согласовано», `in_review` → «На согласовании» (акцентный
цвет), `draft` → «Черновик».

## Токены
Цвета: ink `#201e1d`; текст второго уровня `#444141`; подписи `#605d5d`;
тонкая линия `#d7d3d3`; сильная линия `#201e1d` (2px); акцент `#ec3013`;
акцент для текста мелкого кегля `#ae1800` (accent-700); лист `#ffffff`.
Радиусы: `0` везде. Тени: нет.
Отступы: 4 / 8 / 12 / 16 / 24 / 32 px; внутренние поля листа 52 / 46 px.
Типографика: Archivo — 400 / 500 / 600 / 700 / 800. Кегли: 62 / 36 / 24 / 19 /
13.5 / 12.5 / 12 / 11.5 / 10.5 / 10 px. Ниже 10px не опускаться.
Печатный минимум контраста: подписи не светлее `#605d5d`.

## Ограничения печати
- Не писать свой `@page`, кроме `margin: 0` (иначе в PDF появятся браузерные
  дата/URL/номера страниц).
- Никаких `vh`, `position: fixed/sticky`, теней, скруглений.
- Шрифт встраивать в PDF (Archivo, latin + cyrillic), не полагаться на систему.
- Изображений в документе нет; референс визуала — только текст (по решению
  заказчика). Если позже появятся превью креативов — оборачивать в ч/б
  (`.grayscale` дизайн-системы).
- Кириллица: проверить перенос длинных заголовков, `hyphens` не включать.
