# ТЗ: экран «Сценарист» — 1M.AGENCY PWA

## Что делаем
Переделываем экран «Сценарист» в мобильном приложении 1M.AGENCY. Сейчас это обычный чат: пользователь пишет запрос текстом, ИИ отвечает стеной текста. Проблемы, которые снимает новый дизайн:

1. **Постановка задачи требует печатать** → бриф собирается касаниями (клиент, формат, цель, хронометраж) + одно поле «о чём ролик».
2. **Ответ нельзя использовать** → сценарий приходит структурой из реплик, каждую можно скопировать отдельно.
3. **Бриф съедает экран после генерации** → сворачивается в одну строку над сценарием.
4. **Сценарий некуда деть** → кнопки «В контент-план» и «В съёмки» прямо под сценарием.

## Файлы бандла
- `1M Agency Сценарист.dc.html` — дизайн-референс (открыть в браузере). На канвасе:
  - **Турн 2 (верхний блок) — это то, что реализуем.** `2a` — шаг 1 «Постановка», `2b` — шаг 2 «Сценарий и правки».
  - Турн 1 ниже — ранние варианты, **не реализовывать**, оставлены как контекст.
- Токены тёмного стекла — см. `design_handoff_glass_theme/glass-theme.css` в проекте (тот же набор переменных).

Референс — **не продакшн-код**. Экран воспроизводится в существующем стеке приложения, по принятым в кодовой базе паттернам навигации и компонентам.

## Fidelity
High-fidelity: цвета, типографика, отступы, радиусы, размеры тач-зон — финальные. Тексты сценария, клиенты, цифры — демо-данные.

## Токены (тёмное стекло)

```
--bg:        #08090B      фон экрана
--ink:       #FFFFFF      основной текст
--ink-2:     rgba(255,255,255,.62)
--ink-3:     rgba(255,255,255,.5)
--glass:     rgba(255,255,255,.07)   основной стеклянный слой
--glass-2:   rgba(255,255,255,.06)   вложенные поля
--line:      rgba(255,255,255,.16)
--line-2:    rgba(255,255,255,.10)
--track:     rgba(255,255,255,.12)
--solid:     rgba(255,255,255,.10)   нейтральная кнопка
--accent:    #D6F53E   --accent-ink: #0A0A0B
--alert:     #FF8A6B
--shadow:    0 10px 34px rgba(0,0,0,.5)
--shadow-s:  0 6px 22px rgba(0,0,0,.4)
```

Стекло: `background: var(--glass)` + `backdrop-filter: blur(26px) saturate(170%)` (для мелких элементов 20–24px) + `border: 1px solid var(--line)` + тень.

Фоновые блобы: три круга 280–320px, цвета `#D6F53E` / `#7B4EE8` / `#F2622E`, `opacity .3`, `blur 84px`, анимация только по `transform` (22s / 28s / 19s, ease-in-out infinite), `will-change: transform`. Никаких изменений цвета и яркости — иначе мерцает. `prefers-reduced-motion: reduce` → анимация отключается.

Шрифты: **Oswald** 500/700 (заголовки, крупные цифры), **IBM Plex Sans** 400/500/600 (тело), **IBM Plex Mono** 500/600/700 (метки, таймкоды, кнопки-капсом).

Рамка экрана: 390×844. Вертикальный флекс: статус-бар 46px → контент → таб-бар 74px (нижние 14px — safe area). Таб-бар: `margin: 0 12px`, `border-radius: 22px 22px 0 0`, стекло, 5 пунктов (ГЛАВНАЯ / КОНТЕНТ / СЪЁМКИ / СЦЕНАРИСТ / ПРОФИЛЬ), активный — акцентная планка 20×3 сверху и акцентная подпись.

## Шаг 1 — Постановка (2a)

**Purpose:** собрать бриф за четыре касания и одно короткое поле, ничего не пролистывая.

**Хедер** (padding 6px 16px 12px): `СЦЕНАРИСТ` Oswald 700 24px letter-spacing .04em; справа стеклянная кнопка `ПОСЛЕДНИЕ` (Mono 700 10px) с акцентным бейджем-счётчиком черновиков (radius 5, фон акцент, текст `#0A0A0B`).

**Карточка брифа** — одна стеклянная карточка radius 24, padding 16, gap 15. Внутри пять групп, у каждой метка Mono 600 9.5px letter-spacing .14em цветом `--ink-3`:

1. **КЛИЕНТ** — строка min-height 44, radius 14, `--glass-2`: квадратик-метка клиента 9×9 radius 3 (цвет клиента) · имя Sans 600 14px · справа `СМЕНИТЬ ▾`. Тап → bottom-sheet со списком 15 клиентов (тот же шит, что в контент-плане).
2. **ФОРМАТ** — три равных сегмента min-height 44, radius 13: `REELS / СТОРИС / ПОСТ`. Выбранный — фон акцент, текст `#0A0A0B`; остальные — `--glass-2` + `--line-2`. Одиночный выбор.
3. **ЦЕЛЬ** — чипы min-height 38, padding 0 13px, radius 12: `ЗАЯВКИ / ОХВАТ / ДОВЕРИЕ / ПРОГРЕВ`. Одиночный выбор, перенос по строкам.
4. **ХРОНОМЕТРАЖ** — слайдер 15–90 сек, шаг 5. Трек 6px radius 3 (`--track`), заполнение акцентом, ручка 26×26 radius 9 белая с тенью; область тапа — min-height 44. Значение справа над слайдером: Mono 700 11px акцентом (`45 СЕК`).
5. **О ЧЁМ РОЛИК** — многострочное поле min-height 76, radius 14, Sans 400 14px/1.45, placeholder цветом `--ink-3`. Под ним два пунктирных чипа-действия (border 1px dashed `--line`): `ГОЛОСОМ` (диктовка через Web Speech API / нативный ввод) и `ИЗ БРИФА КЛИЕНТА` (подставляет сохранённый бриф клиента).

**Блок «ЧТО УЖЕ ЗАХОДИЛО У КТВ»** — под карточкой: 2–3 прошлых сценария этого клиента с лучшим результатом. Строка: текст хука Sans 400 13.5px + метрика справа Mono 700 9.5px (акцентом, если результат выше медианы, иначе `--ink-3`). Тап — подставить как ориентир в поле «о чём ролик». Если у клиента нет истории — блок скрывается целиком.

**Док над таб-баром** (flex: none, не скроллится):
- Кнопка `НАПИСАТЬ СЦЕНАРИЙ` — min-height 52, radius 17, фон акцент, Mono 700 12px letter-spacing .1em. Disabled, пока не выбран клиент и поле «о чём» пустое.
- Подпись `ЧЕРНОВИК СОХРАНЯЕТСЯ · РАБОТАЕТ ОФЛАЙН` Mono 500 9.5px `--ink-3`.

**Скролл:** скроллится только средняя область (карточка брифа + история). Хедер и док зафиксированы.

## Шаг 2 — Сценарий и правки (2b)

**Purpose:** прочитать, поправить и растащить сценарий по местам.

**Хедер** (padding 6px 16px 10px, две строки, gap 9):
- Строка 1: кнопка «назад» 36×36 стекло radius 12 (`←`) · `СЦЕНАРИЙ` Oswald 700 20px · справа селектор версии `В2 ▾` (стекло, Mono 700 10px) → меню со всеми версиями, можно вернуться к любой.
- Строка 2: **свёрнутый бриф** — стеклянная строка min-height 44 radius 15: метка клиента · `КТВ` Sans 600 14px · `REELS · ЗАЯВКИ · 45 СЕК` Mono 600 9.5px `--ink-3` · справа кнопка `БРИФ ▾` (`--solid`), раскрывает карточку брифа шага 1 для правки. После правки — кнопка «Перегенерировать».

**Скролл-область:**
- Строка метаданных: `ВЕРСИЯ 2 · 23:37` слева, линия-разделитель, `≈ 46 СЕК · 96 СЛОВ` справа (Mono 600 9.5px `--ink-3`). Хронометраж считается по словам (~2.5 слова/сек для русского) и пересчитывается после каждой правки; если он расходится с заказанным больше чем на 20%, значение подсвечивается `--alert`.
- **Карточка сценария** — стекло radius 24. Шапка: название сценария Oswald 700 12px letter-spacing .08em + акцентная кнопка `КОПИЯ ВСЕГО` (min-height 30, radius 10).
- **Реплики** — блоки, разделённые `border-top: 1px solid var(--line-2)`, padding 12px 14px, gap 7:
  - строка-метаданные: бейдж роли (min-height 20, padding 0 7px, radius 6, Mono 700 9px) · таймкод `0:00–0:04` Mono 600 9.5px `--ink-3` · справа кнопка копирования 30×30 radius 9 (`--solid`);
  - текст реплики Sans 400 14px/1.45, `text-wrap: pretty`.
  - Роли: `ХУК` (бейдж акцентный), `СУТЬ`, `АРГУМЕНТ`, `ПРИЗЫВ` (бейджи нейтральные `--solid`). Это **роль реплики в ролике, а не план съёмки** — кадров, планов и монтажа в выдаче нет.
  - **Уточнения:** если ИИ не хватает факта, он ставит инлайн-плейсхолдер прямо в тексте — подложка `rgba(255,138,107,.16)`, border `rgba(255,138,107,.4)`, radius 5, Mono 600 12.5px цветом `--alert` (напр. `срок ответа?`). Внизу блока счётчик `N УТОЧНЕНИЙ У КЛИЕНТА`. Тап по плейсхолдеру — поле ввода, значение подставляется в текст.
  - Долгий тап по реплике — меню: переписать только её / удалить / перенести.
- **Кнопки вывода** в конце скролла (две по flex 1, min-height 44, radius 14, `--solid`): `В КОНТЕНТ-ПЛАН` (создаёт пост со сценарием в теле, дата = ближайший свободный слот клиента) и `В СЪЁМКИ` (создаёт задачу на съёмку). Обе — внутри скролла, чтобы не конкурировать с полем правок.

**Док над таб-баром:**
- Ряд чипов быстрых правок (горизонтальный скролл, min-height 34, radius 11, стекло): `КОРОЧЕ`, `ДРУГОЙ ХУК`, `ПРОЩЕ`, `+ ЕЩЁ` (раскрывает полный список: «жёстче», «добавить цифры», «убрать канцелярит», «под сторис»). Тап по чипу = отправка правки без печати, создаётся новая версия.
- Поле правок: инпут min-height 48 radius 16 (`--glass-2`, placeholder «Что поправить?») + акцентная кнопка отправки 48×48 radius 16.

**Состояние генерации:** после нажатия «Написать сценарий» блоки реплик появляются по мере стриминга — сначала скелетон карточки с четырьмя пустыми блоками, каждый заполняется текстом по приходе. Кнопки вывода неактивны, пока стрим не закончен.

## Поведение и данные

**Навигация:** Сценарист — четвёртая вкладка таб-бара. Шаг 1 → шаг 2 — push внутри вкладки, «назад» возвращает к постановке с сохранённым брифом. `ПОСЛЕДНИЕ` в хедере шага 1 — список сохранённых сценариев и черновиков.

**Персистентность:** бриф сохраняется в локальное хранилище на каждое изменение; при возврате на вкладку восстанавливается. Версии сценария хранятся локально и синхронизируются, когда есть сеть.

**Офлайн:** постановка брифа и чтение сохранённых сценариев работают офлайн. Генерация требует сети — при её отсутствии кнопка показывает `НЕТ СЕТИ · СОХРАНИТЬ ЧЕРНОВИК`.

**Клавиатура:** при фокусе в поле «о чём ролик» / «что поправить» док поднимается над клавиатурой (`env(safe-area-inset-bottom)` + высота клавиатуры через VisualViewport API), таб-бар скрывается.

**Копирование:** копия реплики — только её текст; `КОПИЯ ВСЕГО` — весь сценарий с таймкодами и ролями, plain text. После копирования — тост внизу.

**Контракт генерации (бэкенд).** Запрос: `{ clientId, format, goal, durationSec, topic, references[] }`. Ответ — не текст, а структура:

```json
{
  "version": 2,
  "title": "Прямо с завода",
  "lines": [
    { "role": "hook", "from": 0, "to": 4, "text": "…", "gaps": [{"label": "срок ответа?"}] },
    { "role": "core", "from": 4, "to": 18, "text": "…" },
    { "role": "argument", "from": 18, "to": 30, "text": "…" },
    { "role": "cta", "from": 30, "to": 46, "text": "…" }
  ]
}
```

Роли фиксированы: `hook | core | argument | cta`. Правка чипом или сообщением отправляется как `{ scriptId, baseVersion, instruction }` и возвращает новую версию целиком.

**Границы ответа ИИ:** только реплики. Не генерировать описания кадров, планы, монтажные указания, хэштеги и подписи — для этого другие экраны.

## Приёмка
- Бриф собирается без клавиатуры, кроме поля «о чём ролик».
- Шаг 1 помещается в экран без скролла при типичном заполнении; кнопка генерации всегда видна.
- Каждая реплика копируется отдельно; весь сценарий — одной кнопкой.
- Свёрнутый бриф занимает одну строку и раскрывается на месте.
- Сценарий уходит в контент-план и в съёмки без копипаста.
- Все тач-зоны ≥ 44px; текст сценария ≥ 14px.
- Фоновые блобы не мерцают: анимация только по `transform`; при `prefers-reduced-motion` статичны; при скрытой вкладке — на паузе.
