# Промт для Claude Code

Скопировать целиком в Claude Code, предварительно положив рядом папку `design_handoff_scriptwriter/`.

---

Реализуй экран «Сценарист» для мобильного приложения 1M.AGENCY.

**Спецификация:** `design_handoff_scriptwriter/README.md` — читай её целиком перед началом, там токены, разметка обоих шагов, поведение, контракт API и критерии приёмки.

**Дизайн-референс:** `design_handoff_scriptwriter/1M Agency Сценарист.dc.html` — открой в браузере. Реализуем **только Турн 2** (верхний блок канваса): вариант `2a` — шаг «Постановка», вариант `2b` — шаг «Сценарий и правки». Турн 1 ниже — ранние варианты, игнорируй.

Референс — это HTML-прототип внешнего вида, **не продакшн-код**. Не копируй разметку: воспроизведи экраны в стеке проекта, используя существующие компоненты, навигацию, стили и паттерны кодовой базы. Сначала изучи, как устроены соседние экраны (контент-план, съёмки), и следуй их структуре.

**Порядок работы:**
1. Изучи кодовую базу: навигация, таб-бар, существующий экран Сценариста, слой работы с API, локальное хранилище, тему/токены.
2. Скажи, что нашёл и как планируешь встроить экран, — до того, как писать код.
3. Шаг 1 «Постановка»: состояние брифа, чипы, слайдер, поле, автосохранение черновика.
4. Шаг 2 «Сценарий»: структурированный ответ, реплики с ролями и таймкодами, копирование поштучно и целиком, чипы правок, версии.
5. Интеграции: «В контент-план», «В съёмки», bottom-sheet выбора клиента (переиспользовать существующий).
6. Стриминг генерации и состояния: загрузка, ошибка, офлайн, пустой бриф.

**Чего не делать:**
- Не генерировать в сценарии кадры, планы, монтаж, хэштеги — только реплики.
- Не менять другие экраны и общие компоненты без отдельного согласования.
- Не добавлять экранов, полей и функций, которых нет в спецификации.
- Не выдумывать цвета: только токены из спецификации.

Если что-то в спецификации конфликтует с устройством кодовой базы — останавливайся и спрашивай, а не решай молча.
